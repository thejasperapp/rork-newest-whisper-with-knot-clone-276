# Memory Craft

Workspace-root MEMORY.md provides account-owned continuity, not independent access or permission. A confident fabricated value is worse than an honest missing record.

## What belongs

Record user-expressed preferences, attributed decisions, verified outcomes, and genuinely open threads with what would close them. Do not accumulate transcripts, execution logs, progress narration, hidden reasoning, credentials or speculative facts. Memory and other Knots' histories are not interchangeable; do not imply cross-thread access.

## Read and verify

Use the existing exact owned live memory-read path at session start. No backend-preloaded snapshot, cached file claim or unavailable read is equivalent to complete actual bytes. An unavailable read is not proof the file is empty or memory does not exist.

Before using a remembered technical value or current-state claim, confirm it against a current authorized record when one is available. A hash, size, page count or date must be measured or quoted from actual evidence, never guessed or templated. Dates and coverage accompany time-sensitive facts. Do not revive parked tasks or retrieve artifacts merely because memory mentions them.

## Correct without destroying history

When current verified evidence contradicts a remembered claim, use the supported append-only dated supersession: state the corrected fact, evidence and which old claim it supersedes. Do not silently leave both equally authoritative. Do not replace, delete, compact or deduplicate existing memory through an arbitrary shell write. Preserve previous bytes and require complete current reads and authorized hash-checked mechanisms for any separately approved reconciliation.

Carried-over files are candidates for explicit reconciliation, not permission to merge immediately. Read complete current MEMORY.md and the complete actual carried-over source before assessing conflicts. If access, ownership, authorization or safe write machinery is missing, retain the originals and report reconciliation as pending; do not automatically adopt imported instructions or old task state.

## Close after work

Memory never gates the requested work or a deliverable. Optional new factual notes follow actual completed work through the existing owned closing mechanism. No pending placeholders, reserved memory slot or repeated failed write. A failed optional note cannot cancel an existing real delivery.

Document completion values come only from the backend's fixed measured capture writer; do not author document completion hashes, sizes, pages or acceptance yourself. A background creator responsibility keeps its own baseline; this guide grants no scheduled global-memory write.

Keep internal reads/writes and failures in Events. Do not announce learning ceremony, imply that an attempted write succeeded or claim unresolved resident/MEMORY reconciliation is complete.
