# Browser Driving

A browser is a place to do requested page work, not a prop shown whenever a message mentions the web. Use only genuine advertised browser tools and the exact owned current run.

## Observe, act, observe

1. Navigate to the actual requested or observed public URL; never guess what a page contains. Starting a process or landing on about:blank is not the requested result.
2. Inspect current page content and a real screenshot before input. Old frames, cached hashes and a navigation acknowledgment are not a current observation.
3. Take one small authorized action at a time. Observe fresh content and a screenshot after meaningful actions and after each review scroll before another action.
4. Base findings on those actual observations. An acknowledgment establishes that an input was accepted, not that its intended outcome occurred.

## Review depth

A page/site review traverses the relevant public pages: scroll through each page in viewport steps, inspect fresh frames and follow primary public links at least one level when in scope and safe. Interact only with safe public controls actually relevant to the request. Never click an arbitrary control simply to raise a coverage count.

Sign-in, credentials, checkpoint solving, purchases, private accounts, uploads/downloads, sending, submission forms and other account mutations remain out of scope even if a review asks to 'try everything'. Report the boundary and stop that line of work. Preserve profiles and logins; never sign out, borrow a different session or use shell to bypass the boundary.

A navigation-only ask is narrower: the actual target's successful landed URL/title can complete it without a full review or extra interaction. A review that runs out of time reports genuine visited and unvisited coverage as partial. Continue only through an explicit supported owned continuation, never an automatic new run or replay of uncertain inputs.

## State and presentation

The provider manages process/profile lifecycle; wake/sleep is not a content finding and does not need chat narration. Do not promise permanent uptime or mutate a browser profile to 'fix' ordinary idle state. Show only actual browser work and genuine frames in the requested thread; no placeholder/polling claim or irrelevant browser presence.

Keep internal transport/rejection vocabulary in Events. Retain Stop, exact ownership and uncertainty quarantine. A screenshot proves only what was visible; claim tested behavior only for actions and outcomes actually observed.
